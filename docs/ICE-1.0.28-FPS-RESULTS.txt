保留的实现
1. 地形上传与绘制存储分离。CPU 写入最多 3 个 1 MiB 持久映射上传槽，显式刷新
   后通过有序 GPU copy 更新不映射的常驻 GL_STATIC_DRAW 地形缓冲。槽位封口/帧末
   建立 fence，最多两次非阻塞探测；忙、预算不足或过大上传走有序 glBufferSubData。
   不再直接长期从 CPU 映射页绘制静态地形；继续保留原资源预算、退休及回退语义。
2. 软件遮挡按近到远处理候选，在上传时为真实合并不透明面预建面积优先序；透视
   投影下先跳过背面，每帧最多选择 128 面。连续无隐藏收益时按 1/3/7/15/31 帧
   退避，有收益恢复逐帧检测，大幅移动/转向提前重试。跳过只增加绘制，不沿用
   历史隐藏结果。保留原 2048 面完整入口作参考，新的元数据纳入内存预算。
3. OptiFine 使用其原生遍历。相同位置的开关消融发现自建 primitive 遍历更慢且
   C 数不同，故在消费队列和改帧标记之前交回 OptiFine。未宣称已定位某个特定位
   掩码错误；普通非 OptiFine 环境的 primitive 实现仍保留。
4. HUD Unicode 文本按连续纹理页片段提交，缓存键包含 Unicode 模式；不改变片段
   顺序、阴影或字形。ASCII 单页保留原快速入口，格式/随机样式/Bidi 继续原路径。
5. 透明排序遇到已经完全有序的距离序列直接结束，省去排序和整块顶点复制；出现
   首次逆序立即使用原稳定算法，保持相等元素及 NaN 的既有语义。

撤回/不采用的候选
地形面区间进一步 glMultiDraw 聚合：普通缓冲微基准及整包对照没有独立净收益，撤回。
解析式软件栅格化替换：没有得到可靠净收益，撤回，保留原保守软件光栅核心。
没有把“CPU 能映射”直接视为“更快”，也没有把仅能减少跑图停顿的工具当作 FPS 方案。

局部验证（不等同于整包 FPS）
同一 640 网格/3,932,160 顶点原生测试：旧持久映射绘制约 8.347 ms，新分离存储
约 0.559 ms；一半外部 VBO 时约 4.181 -> 0.611 ms，图像一致。
这证明本机驱动上两种存储路径差异巨大；没有测得物理内存放置，不能断言必在系统内存。
240 次不同大小且重叠目标范围的上传，GPU 回读 4 MiB 全部正确，221 次暂存、19 次
过大回退；输入游标和 COPY 绑定不变，目标未映射，重复 close 后预算归零。
混合 VBO 顺序/跨页/重建等原生检查通过；最新 12 视图的像素最大误差全部为 0。
HUD 原路径的 72 组像素哈希与 1.0.27/新路径各轮一致，旧/新路径已复测 7 轮。
第 7 轮同页中文 9.958 -> 2.707 us，
中英跨页混排 13.099 -> 3.542 us；短文本仍可能慢于原路径，不宣称所有字符串都更快。
有序透明顶点组在 1024/4096 组时约 20.8/84.0 -> 6.6/25.5 us；随机输入基本持平。
