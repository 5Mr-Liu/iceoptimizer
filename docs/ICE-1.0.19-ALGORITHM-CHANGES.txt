ICE 1.0.19 算法改进与离线对照
2026-10-10

本轮在 ICE-1.0.19-PERFORMANCE-FIXES.txt 中的修复之上，继续减少现有优化本身的工作。实现参考原始项目源码和 API 规范，再按 Minecraft 1.12.2 的调用顺序适配；没有直接移植其他版本的渲染器。
下列耗时均是本机 Java 8 的离线函数对照，不是游戏 FPS。正确性对照、计数和计时工具只存在于测试/tools 中，没有塞进运行时。

1. 普通模型：整组拒绝改为连续部件分段合批

ModelBiped / ModelQuadruped 原来预先收集整组 7 / 6 个根部件，一个根部件不支持就整组失去共享状态合批。本次改为按原顺序收集连续可处理的根部件，遇到不能处理的根部件先结束当前批次，执行其原始回调，再从最新的模型字段继续下一段。
没有跨未知回调保存后续部件的计划：回调可以隐藏、替换后续部件或修改 GL 状态。部件子树收集到一半失败时，只撤销这个子树已收集的条目，之前完整的根部件仍可合批。
全部可处理的模型保留一次 begin/end 的路径；只有分段模型进入逐根边界处理。没有添加每帧模型缓存校验、计时筛选或跨帧黑名单。
真实 Forge / OptiFine G5、成人/幼年、两种模型、VAO/pose 路径对照均保持像素一致。一个 28 部件的测试模型夹着 4 部件的未知根时，从整组 28 次绘制变为两段 pose draw 加 4 次原绘制，共 6 次。这个结果用于证明分段能减少工作，不能推断所有游戏模型都有相同收益。
参考：VAO 保存顶点输入状态，以及减少细碎绘制提交的原则；具体分段与回调处理为 ICE 实现。

2. 透明四边形：大批次稳定基数排序

旧实现已去掉装箱，但仍对所有规模执行 O(n log n) 归并比较。新实现对至少 512 个四边形使用间接 LSD 基数排序，将浮点距离转成与 Float.compare 降序一致的整数键，最多进行四次稳定字节分配。
四个直方图在计算键时一次生成；某个字节全部相同时，无需执行该轮分配。小批次继续使用原有浮点归并排序，避免固定直方图成本。512 是算法选择的固定规模界限，不是帧率门禁，也不会关闭排序优化。
NaN 按 Float.floatToIntBits 规范归一，使不同 NaN 保持稳定的原顺序；正负零、无穷值、相等距离均与原比较语义一致。顶点有效载荷仍以原始整数复制，不转换颜色或 UV 数据。排序工作区复用，没有逐帧分配比较器或装箱索引。
复杂度：大批次排序为 O(4n + 1024)，顶点载荷搬运仍为 O(n × 顶点步长)。线程工作区的距离键替换旧浮点距离数组，另增加约 6 KiB 固定直方图/小数组空间。
随机输入的完整距离计算、排序和顶点搬运中位数（微秒，旧 -> 新）：
  512 quads     12.36 -> 9.68
  1024 quads    38.68 -> 18.97
  4096 quads   275.72 -> 77.66
  16384 quads 1361.14 -> 414.37
重复距离输入也有改善。但预先有序输入的比较分支容易预测，基数排序并非总占优势：1024 quads 的同轮对照为 21.07 -> 24.22 微秒，4096 为 96.83 -> 104.34 微秒。小批次代码保持原算法，计时仍有 JIT/CPU 噪声。没有加入在线计时或自动停用来掩盖这些取舍。
验证覆盖算法切换边界、多个顶点步长、移动观察点、极值/NaN/相等键的完整载荷顺序，以及 100000 对 IEEE 浮点数的键顺序。另有独立对照验证 88 组同一工作区跨大小切换及双端序输入，16 种统一字节组合各运行 3 轮，覆盖 0–4 次实际分配的结果。
参考：原始稳定 LSD 分配算法、fastutil 浮点基数排序实现及 Java 浮点比较规范。代码为 ICE 自行适配，没有新增依赖。

3. 地形遮挡：按深度块排除无效写入，合并达到不动点后结束

已有扫描线栅格器仍逐格执行 min/写入，即使近处墙面已经完全遮住后面的面。本次给现有每行 8 格的小块保留一个深度上界；新面深度大于等于该上界时，该块所有 min 运算都不可能改变结果，因此跳过写入和缓存失效。
完整小块的精确最大深度可以直接用 min(旧最大值, 新深度) 更新；部分覆盖只在数值确实变化时标记其精确摘要失效。上界不直接用于判定区块隐藏，查询仍使用原来的精确深度。每帧重新初始化，移动视角同样适用，不复用上一帧可见性。
在 160 × 90 分辨率下增加固定 14400 字节的块上界数组，原来的逻辑工作量计账、近裁面、覆盖边缘和查询顺序不变。重复覆盖时，工作从逐格更新转为逐块跳过。
遮挡面矩形合并原来固定 U/V/U/V 排序。一个完整 U/V 周期没有合并时，矩形值已经达到不动点，继续相同周期也不会改变结果；此时结束，保留相同的最终 V 顺序。
600 个变化视角、7200 个随机面及最多 36000 次交错查询逐项对照所有深度格、查询结果和剩余工作量；1000 个网格捕获输入对照合并后的精确顺序、坐标和边界，均一致。
离线计数：8 面重复墙的深度写入 115200 -> 14400；512 个无法合并的面排序次数 4 -> 2。静止和移动重复墙均减少相同数量的写入。
内核对照中重复墙约 123 -> 35 微秒；但更完整的 4096 项遮挡筛选只有约 0.576 -> 0.522 毫秒，其他多组差异接近噪声。没有可消除写入的微小面测试约增加 1 微秒，包括新增固定数组清空成本。不能将内核倍率当成整帧收益。
参考：Intel/GameTechDev 原始 MaskedOcclusionCulling 的粗粒度深度比较与分层摘要思路。这里保留 ICE 原来的精确标量深度语义，没有加入 SIMD 依赖或 CPU 特征检测。

4. SRP 刷怪过滤：把热循环的哈希查询压缩成数组下标

原实现每次过滤都清空两张整数哈希表和一张 Class 身份表，并在列表循环中反复查询。现有编译列表已经捕获不变的寄生体 ID 和实体类型，因此现在编译时为不同 ID / Class 分配连续编号；每次过滤的动态结果使用三张 byte 数组直接索引。
动态资格、殖群和数量上限仍在本次调用重新求值；回调第一次执行的顺序、殖群总数的惰性计算、返回条目对象及顺序不变。没有延长缓存到下一 Tick，也没有增加扫描世界的检测。
稳态复杂度仍是 O(n)，减少的是哈希、探测和清空的常数成本。每个编译列表增加两个整数索引数组（约 8 字节/条目）；临时工作区用紧凑字节数组替换三张决策哈希表。
500 个随机列表、每个列表三轮变化条件，共 1500 次对照，以及真实 SRPMixins 2.9.2.2 字节码适配验证均通过。列表替换、负 ID、极值、重复 Class 和空 Class 的结果一致。
两种运行顺序的离线结果一致地改善，例如 128 条、重复 ID 的过滤约 0.90 -> 0.54–0.61 微秒；128 条全唯一约 1.28–1.31 -> 0.64–0.70 微秒。这是服务端刷怪过滤函数的工作量下降，不保证转化为客户端可见 FPS 提升。
参考：SRPMixins 原始过滤顺序及 Agrona 哈希表的查询/清空实现。实际安装版本另外通过 javap 与适配测试核对，未将上游当前分支直接当作已安装代码。

其他已检查的算法
SRP 目标选择已有单次最小值选择，数量上限已有单次实体遍历；没有为了扩大改动量重新实现相同算法。路径缓存限定在同次寻路，跨 Tick 复用需要维护方块变化依赖，本次不增加这类成本与失效逻辑。
地形 MDI 混合原始绘制/物理页仍会形成小批次；任意重排可能改变共面像素，未用重排制造更高合批数字。普通模型分段也只解决已有 Biped / Quadruped 路径，不能据此声称录制中全部未合批部件都已覆盖。
