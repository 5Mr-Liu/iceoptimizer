# ICE 1.0.10 现场卡顿优化测试版

本次检查了 DregoraRL2 在正确安装 Optimizer 1.0.9 后的 14 份记录（2026-10-02 03:46–03:57），并针对记录中可确认的开销和渲染覆盖问题修改代码。优化器继续使用单个安装 JAR。游戏内 FPS 和瞬卡改善需要用户实测。

## 现场发现

- 实体和 TESR 现代后端在 8 个无候选 Modern 测量帧后进入永久 Legacy；后续模型批次、Modern draw 和页绑定均为零。缓存已有 704 个部件，但实体/TESR 缓存 miss 累计分别约 39.6 万/29.8 万。原捕获开关排除了初始化和 WARMUP，部分只编译一次的常见模型无法在后续补捕获。
- 03:49:51 的服务端 Tick 耗时 39.12 秒。该事件保留的 632 个服务端样本中，211 个停在 BO3 原始文件打开，120 个停在 ICE 文件路径解析；该会话没有字典溢出。这是事件末尾采样证据，不代表整段 Tick 的时间占比。许多同时段客户端帧仍很短，因此要区分画面卡顿与服务端世界生成停顿。
- 03:50:43 的 2.42 秒服务端 Tick 仍含 ICE 缺失路径解析；03:51:21 的 897 毫秒 Tick 含设置冷加载。03:52:01 的 9.81 秒 Tick 还涉及 OTG BO4 结构资源解析。
- 03:53:26/03:54:56 的客户端尖峰分别约 1.10/1.58 秒，保留的样本主要停在 SocketInputStream.socketRead0。旧记录器在栈字典溢出后把相同顶部三帧复用为历史完整栈，因此不能据此认定具体调用者。此次修复记录器后再记录，可避免误归因。

## 修改与开销清理

模型捕获允许初始化和暖机期间的一次编译，也允许仍有更重负载重测资格的 Legacy 后端在冷却期间捕获新模型。普通绘制钩子继续在休眠时旁路。未得到候选的模型验证/测量进入等待状态；冷端新网格成功发布后恢复原先未完成的验证或 ABBA 测量。待发布队列能唤醒帧基础设施，发布时按模块丢弃旧 GPU 测量关联；Query 仍由原正常轮询释放。

轮廓对象原本禁止 Modern 绘制，现在也不再计为 Modern 候选。600 帧无进展判断使用本轮实际提交记录，避免把 GPU 结果延迟或场景不稳定误判为缺少几何。实测收益不足、正确性失败、能力自检失败继续使用原回退；5% 中位数收益与 2% P95 回归门槛保留。新的恢复状态仅在冷编译/发布边界工作，不给每个部件增加重试或 GPU 查询。

OTG 在普通真实目录中复用现有目录监听对象保存的父路径，目录事件和监听失效使其失效；目录链接/别名不缓存真实路径，文件符号链接仍单独解析目标，避免上级目录重定向后读到旧位置。删除未被读取的内容 SHA 计算与元数据额外整文件读取、相邻重复属性读取、设置缓存命中的第二次目录轮询，以及元数据解析后的临时对象树。实际文件读取前后的一致性检查、配置换代和返回独立可变 NBT 的行为保留。与此前一样，热命中依赖目录事件送达后失效；Windows WatchService 异步通知可能晚于紧接着的读取。变更测试等待实际监听证书失效后验证重读/删除，不在生产热路径添加睡眠、逐次属性查询或等待。

BO3 原始打开在 metadata cache miss 后执行；真实 9.7 的 cache hit 已位于 FileInputStream 打开之前。采样次数不能证明同一个文件被重复打开，此次没有据此改动结构生成顺序、随机数或世界数据。

Profiler 正常帧只记录历史窗口，超过绝对门槛的长帧才计算自适应阈值；两组工作数组复用。HUD 复用稳定指标文字，诊断摘要只在完成/次数变化时重建。网络计数器按 Channel 去重安装，失败、断线换 Channel 和 handler 移除后仍可重装。字典溢出时用有符号 prefix ID 导出确定的顶部方法和截断标记，精确栈不变，v4 报告格式不变。同一栈的纯调用链分析继续复用，线程角色/状态按每个样本判断，修复同一栈不同状态被错误复用为限帧等待的旧问题。
