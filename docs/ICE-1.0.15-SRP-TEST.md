# ICE 1.0.15：SRP 优化与游戏测试

安装包：`build/libs/ice-rlcraft-optimizer-1.0.15.jar`。本轮没有替换游戏实例里的模组，也没有启动游戏。

## 已整合的七项方案

| 项目 | 实现与边界 |
| --- | --- |
| 攀爬寄生体寻路 | 8 类共用的 `PathNavigateClimberStatus` 和 Ata/Mudo/Nuuh 的原版攀爬导航接入现有单次寻路节点缓存。原爬墙、无路径追踪、到达停止和状态判断保持原方法。 |
| 生物上限计数 | SRPMixins 每次世界事件中的 7 个原始计数调用共享一次实体遍历，按原配置和维度只计所需类别。保留持久实体排除、子类归属、原计数发布时间以及独立 SRPExtra 调用。 |
| 殖群总分 | 同次刷怪过滤内，所有需要殖群总分的寄生体 ID 共享一次惰性计算；没有需要时不计算，下次过滤重新计算。 |
| 寻光扫描 | 扫描范围、顺序、随机调用与任务频率不变。复用一个查询坐标，直接选最近位置，单次扫描缓存纯方块名字判断，用 primitive 集合查询不可达位置。 |
| 弱点规则 | 原生 SRP 弱点循环改用名称索引和已解析倍率，重复规则仍按原顺序逐次 float 相乘。SRPMixins 2.9.2.2 已有自己的弱点编译，启用该修复时仍执行其原有路径，不能把本项算作叠加收益。 |
| Heblu 动画 | 同次姿态求值内复用相同余弦表达式：正常地面分支 16 次降至 2 次，飞行分支 4 次降至 2 次。每个肢体的后续运算不变，没有跨帧或跨实体姿态缓存。 |
| 感染名单 | 缓存纯名字子串匹配的正、负结果。通过 Mixin 的 postApply 接入合并后的感染/群系方法，保留硬度、位置、事件、现有白名单分支与上游正缓存行为。 |

配置数组发布时清理对应规则缓存；没有每 tick 配置扫描。新增 `srpMobCap`、`srpInfestationCache`、`srpLightSearch`、`srpWeaknessRules` 默认开启，Heblu 使用现有 `srpPoseCache`。

F6 继续切换所有可即时关闭的 **ICE** 优化；SRPMixins 自己提供的优化不会随 ICE 的开关关闭。没有增加在线收益测试、等待静止、预热帧数或 ABBA 启用门槛。

## 游戏中如何对比

替换旧 ICE 为 1.0.15；多人游戏的客户端和服务端使用相同版本。使用同一群寄生体、相同视距与画面设置，按 F6 切换，并分别观察站立、移动、转视角、战斗和感染扩散。

Heblu 优化主要减少客户端动画计算；寻路、计数、刷怪与感染优化主要减少世界 tick 工作，可能表现为战斗和移动更平稳，不能仅由 FPS 判断。真实 FPS、帧时间与 tick 收益尚待游戏实测，上述次数减少不代表等比例帧率提升。

## SRP 条件复查与清理

- 刷怪过滤删除“至少 4 项”门槛和 `RandomAccess` 类型限制；0～3 项及顺序列表也能进入优化路径。同次殖群总分共享因此覆盖短列表。删除与实际是否使用该参数无关的提前空值拦截。
- 顺序列表使用迭代器编译和核对，避免取消类型限制后出现按下标访问链表的平方级开销。列表内容变化核对保留，防止同长度替换后仍使用旧的刷怪条目。
- 目标搜索取消 `RandomAccess` 限制，统一稳定线性选择；启用时空列表/单项列表直接返回，F6 暂停仍执行上游排序。
- 生物上限结果由注入点传入固定下标直接读取，删除运行时类别查找循环及其不可达的“不认识类别”异常分支。
- 删除 Kirin 显示列表中永不成立的根身份比较与重复引用；删除寻路分类必定返回枚举时的两处空值判断。

保留 F6、原游戏筛选条件、缓存有效性和启动时的字节码结构匹配。旧 Kirin 显示列表的稳定观察与重编译冷却仍保留：其子树变换会烘焙进显示列表，盲目取消会使活动分支每帧重新编译，反而增加开销。新增的 Heblu 姿态复用不受该显示列表条件限制。

回归测试覆盖短列表共享、顺序列表无下标访问、同长度条目替换、F6 暂停/恢复、稳定最近目标选择和固定计数下标；完整构建日志为 `.refactor-backups/1.0.15-srp-condition-cleanup-build.log`。
