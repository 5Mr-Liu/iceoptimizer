User requirement
---------------
Default to enabled. F6 must switch the enabled ICE optimizations off/on together,
including native terrain, preserving individual configuration and compatibility
decisions. The user will remove the separate profiler; do not alter its HUD or
deploy into the original game. This explicitly requested manual switch is not
an automatic performance gate or adaptive fallback.

Implementation
--------------
First launch and older configs missing nativeTerrainRenderer now select native
terrain immediately. Explicit enabled=false/nativeTerrainRenderer=false and
external Nothirium ownership remain respected. Bootstrap tests cover both cases.

The existing registry pause already clears both operational masks and stops ICE
workers, render submissions, async skull lookup and compression producers.
Keep that shared gate, including rejection/disabled state on resume. Many
bytecode-installed optimizations already have an original branch selected by
the module gate (for example NormalStringPool's constant-key rewrite); installing
a bytecode hook at startup does not by itself mean the algorithm stays enabled.

Native terrain was the important missing execution path: its four original
entry points had been discarded. Retain the incoming setupTerrain,
renderBlockLayer, VboRenderList.renderChunkLayer and dispatcher VBO uploader in
private synthetic methods. A single pause check selects the incoming body on
F6-off. On F6-on the native traversal/upload/draw body remains direct. Preserve
other mods' incoming implementations rather than reconstructing vanilla code.

On the client thread, drain/cancel chunk construction before changing the gate,
release native GPU ownership, then reload terrain in the selected mode. Rebuild
in both directions; do not share arena ranges with vanilla per-chunk VBOs or
retain a second GPU copy. Clear upload context while paused. The same lifecycle
is in ClientOptimizerRuntime.setRuntimePaused, so F6 and the test fixture use
the same implementation. Repeated requests for the same state do not rebuild.

The change does not unload classes or reverse already completed initialization.
Added interfaces, existing data and mutation/invalidation bookkeeping remain
resident for correctness when resuming. This is an execution/FPS comparison,
not a no-JAR startup-time or heap-residency comparison. Other mods are unaffected.
Both transitions rebuild chunks and can hitch; compare only after settling.

Superseded after user report (2026-10-13)
----------------------------------------
Build15's smoke test missed a real F6 deadlock during chunk rebuilding. The
actual key-handler stress test reproduced it on switch four. Do not distribute
Build15. Internal Build16 fixes cancellation before the blocking dispatcher
drain; all six stress switches completed. The user requested release version
1.20 for this substantial update. See ICE-1.0.30-F6-DEADLOCK-FIX.txt for the
reproduction, fix and validation, and the 1.20 package for the release artifact.
