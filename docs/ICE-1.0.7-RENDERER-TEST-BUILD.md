# 1.0.7 渲染器测试包

日期：2026-10-02。继续使用 1.0.7 版本号，在上一轮实体渲染精简上加入生产状态批次、Mo’ Bends 姿态矩阵复用和 HZB 确认/测量修复，并清理这些新增路径中的重复工作。本包用于后续游戏实测，未发布到 GitHub。

## 实际接入

模型状态批次在原绘制位置即时执行全部矩阵和部件绘制，共用一次客户端数组设置及恢复。已审查的 Forge / OptiFine G5 ModelRenderer 模型子树可以使用此路径；预检结果保存在复用数组中，活动批次直接使用已找到的网格，不再逐部件重复运行完整接管判断。一个根的预检失败后，在其渲染结束前抑制后代重复预检，避免不合格长链产生平方级扫描。叶部件不进入树预检。

常见 ModelBiped / ModelQuadruped 的多个独立部件也已接入一组状态批次。Biped 按原顺序收集头、身体、右臂、左臂、右腿、左腿、头部外层，Quadruped 按头、身体和四条腿收集。作用域在每分支第一次头部绘制前开始，原 setRotationAngles 动画虚调用、Biped 成人分支的 isSneaking 回调及条件平移已执行完毕；成年/幼年矩阵分支完整保留。无需逐帧建立根数组；未知 render 扩展不注入作用域。

每个已接管部件原先使用 10 次原生 GL 调用，N 个部件的状态批次使用 5N+5 次；16 个部件从 160 次降至 85 次。部件矩阵、纹理、绘制顺序及 GPU 部件绘制次数保持原语义。这轮完成的是状态与提交开销合并，跨不同姿态的几何合并和 GPU 实例化仍未实现。

只在实际方法图已审查、部件已编译且网格可用的范围内保持数组状态。G5 的纹理覆盖、ModelUpdater、Sprite 和待重置显示列表不进入批次；自定义部件、List 子类及未知方法扩展继续即时原路径。方法图在类转换时验证一次，热路径直接读取注入的字段访问方法。新增接口随 Core 打包，Main 不含重复定义。

Mo’ Bends 的 ModelPart.applyLocalTransform 已调用四元数缓存。CPU 姿态和 GL 提交共享相同原始浮点输入的旋转转换结果，内部矩阵与存储数组复用；四元数变化时更新。目标矩阵乘法、平滑更新和原动画副作用完整执行，没有降低可见实体动画更新频率。

HZB 发现隐藏候选缺少独立确认时，申请新深度发布；同一历史图不能充当第二份证据。确认后恢复长期复用，新候选加入时再次取证；确认表预算不足时保留绘制且不反复捕获。OUTPUT_VALIDATE 只由独立 source-depth oracle 发布推进，重复检查同一张图不累计成功次数。

HZB 的 Legacy / Modern GPU 计时现在都从 SOLID 开始到 CUTOUT 后结束。复用历史时正常保留、关闭并提交测量样本，首次补采深度的 Legacy 样本仍排除；缺少收尾钩子时丢弃不完整样本。保留异步回读及双次保守确认。

## 新增路径的冗余清理

- 模型批次预检已确认部件、网格认证、资源存活与代次；经过审查的同步范围内没有回调、资源回收或帧换代。批次绘制删除逐部件重复的线程、网格认证、资源查表、代次和固定管线状态检查，省去相应 ThreadLocal、装箱及映射查找。普通即时路径继续按原契约检查；原矩阵指令可能使跟踪失效，逐部件矩阵有效性检查保留。
- 模型绘制统计从每部件上报改为每批结束后按实际成功数上报一次。N 个部件的同步 profiler 调用由 N 次降至一次，两个 traversal 计数共用一次查找；顺序失配、矩阵拒绝、渲染异常或恢复失败时仍记录此前成功提交的部件，当前回退部件不会重复计数。候选成功后重复 stamp 空检查及重复生命周期读取也已清理。
- Mo’ Bends CPU 姿态缓存命中不再读取、重置 GL FloatBuffer；CPU 与 GL 入口共用输入验证和转换，目标矩阵只做一次类型转换。三个模块开关使用已有 ordinal 接口，省去每次字符串哈希及模块映射。四元数原始位比较、配置开关和熔断继续生效。
- HZB 输出验证合并可用性与验证入口的重复视图、矩阵及代次匹配。每幅不可变深度金字塔仅在首次输出验证时完整检查层次，后续复用结果；普通运行阶段不新增全图检查。视图、资源、图像关闭状态、候选投影和独立发布确认仍实时检查。

类转换时的方法图验证只执行一次。G5 回调/纹理排除、模型子类和 List 子类识别、待编译检查、批次顺序、递归上限和异常状态恢复直接约束绘制语义，因此继续保留。拒绝根的 scopeOpened 也保留，用于防止后代反复扫描同一不合格树。

## 局部验证

完整 `build optimizerBundleZip` 通过：202 个测试类、810 项测试，780 项通过、30 项因未提供对应可选依赖而跳过，零失败、零错误。输入包含真实 Forge SRG/client、OptiFine G5、LLibrary、RenderLib 1.4.5、Mo’ Bends 和 Lycanites JAR，模型方法图、两种年龄分支及 HZB 确认/测量生命周期均有行为或真实字节码覆盖。此前扩大输入后修正了一个旧 RenderLib 集成测试对列表入口的过时断言，生产 RenderLib 行为未改变。本次增加 8 项行为回归，覆盖批次正常/部分回退/清理异常的精确统计、诊断计数饱和、CPU 与 GL 缓存交错、不可用视图及坏/已关闭深度图。

`tools/ModelStateBatchProbe.java` 调用生产 LwjglModelMeshCache 的即时/状态批次方法，在不可见 Pbuffer 中比较 16 个独立变换部件。普通、透明混合、深度测试三种场景像素逐字节一致；数组缓冲区、数组布局/启用、第二纹理单元数组状态以及软件绑定镜像恢复一致，GL 错误为零。清理后再次验证通过，并确认矩阵失效时不发出批次绘制且恢复状态。GPU 为 NVIDIA GeForce RTX 4060 Laptop GPU。该探针验证原生提交与状态恢复，不测整套模型预检或游戏 FPS。

真实 Mo’ Bends JAR 行为对比覆盖 256 组四元数、每组 3 个 pass，含有符号零、极值、非有限值及 NaN；目标矩阵 double 原始位与原实现一致，输入变化后正确刷新并复用存储对象。

上一轮 `tools/MoBendsPoseReuseBenchmark.java` 调用真实原/注入旋转 API，四个独立 JVM 顺序执行，每轮 320,000 次旋转、预热 4 轮、测量 7 轮取中位数：

| 场景 | 原实现 | 复用实现 | 每次分配 |
| --- | ---: | ---: | ---: |
| 姿态不变 | 46.72 ns | 28.07 ns | 432 → 144 B |
| 每次改变姿态 | 50.40 ns | 43.49 ns | 432 → 144 B |

新旧校验和一致。结果包含共同调用/循环成本，未包含首次缓存建立和包装入口的模块判断；不能据此换算 FPS。

本次姿态冗余清理前后对比记录在 `build/performance-audit/renderer-pose-cleanup-benchmark.txt`：稳定输入 32.24→32.21 ns，变化输入 46.72→46.57 ns，每次分配仍为 144 B，校验和一致。时间差在噪声范围内，没有测出显著速度收益；字符串模块开关不在该基准覆盖范围。
