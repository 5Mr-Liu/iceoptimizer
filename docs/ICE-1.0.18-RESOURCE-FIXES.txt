ICE 1.0.18 共享渲染资源修复

针对 2026-10-10 的 1.0.17 录制：共享 GPU 预算只剩约 2 KiB，地形与粒子在同步对象创建阶段回退，模型新增 139 万次录入均失败，整模型合批计数为 0。

本次改动

同步与对象生命周期
- 删除同步对象、program、shader、VAO、FBO、query 人为假定的 4 KiB / 64 KiB 显存收费。这些对象继续创建、跟踪、同步及销毁，真实原生错误仍会报告。
- 真实 buffer / texture 存储仍按申请量计入原有共享预算。没有提高默认 256 MiB 上限，也没有新增固定的后端保留池。
- 缓存填满不能阻止用于完成和回收已提交数据的同步对象创建。预算数字代表 ICE 管理的存储申请量，不是显卡驱动实际显存使用量。

地形存储
- 保留原逻辑页与最大网格容量，物理页按实际范围从 256 KiB 起逐级增长，避免小量网格立即占用完整 16 MiB。
- 扩容用 GPU copy 保留旧内容；已排队绘制、旧 VAO 与缓冲的退休顺序保持有效。持久映射写入与未完成复制之间保留必要的同步顺序。
- 实际存储申请失败时，先零等待收集已完成的退休范围和空页，再重试申请；没有新加每帧全量回收扫描。
- 不支持 GPU copy API 的旧上下文沿用完整物理页布局；这是冷初始化时选择实际可用的实现，不是硬件白名单。

模型录入
- 删除按帧退避与每帧遍历整个失败队列。新任务进入待处理队列；容量不足的任务等待已登记存储真正释放、内部范围可复用或所需 direct 空间可用。
- 没有就绪任务时跳过录入所需的 GL 状态认证；正常处理继续使用原每帧任务量上限，不新增冷却时间。
- 在获得存储后才复制上传数据；纯容量拒绝不执行无用的 GL 绑定恢复。

HUD / FBP / 粒子
- HUD 和 FBP 由按最大配置预占改为按当前批次创建或扩容槽。
- 普通存储不足使用原始绘制，保留后续恢复能力，不把预算压力当作后端故障。
- 旧槽仍等待自身 GPU 工作完成后才复用。真实粒子、HUD、FBP 与模型共享同一预算进行组合验证。

没有新增 FPS 收益判断、摄像机静止条件、固定等待帧数、在线 A/B 准入、硬件白名单或诊断采样。
已提交内容不能重复绘制、不能提前覆盖 GPU 使用中的数据，以及实际 API 能力和资源代次等正确性条件继续保留。

验证与安装

- Java 8 / Gradle 4.9 完整离线构建成功。常规测试 1063 项通过、20 项跳过；产物启动测试 10 项通过；无失败或错误。两个安装 JAR 均标记 1.0.18，未打入 IvToolkit 类。
- 最终编译产物通过 8 组真实 OpenGL 验证：模型 VAO、姿态合批、真实 Forge/G5 矩阵边界、模型待上传队列、地形分页/扩容、地形绘制、粒子预算、多个后端共享预算。
- 模型队列复现 3378 项：容量不足各尝试一次，71 次有界处理后进入等待；连续 10000 次帧检查新增尝试和检查条目均为 0；真实资源释放后全部恢复录入，GL 绑定正确恢复，最终无预算泄漏。
- 同一 ledger / budget 下，真实地形缓冲占满后，模型上传和粒子/HUD/FBP 新批次正常回退；地形回收后全部恢复。再次填满真实存储预算时，已缓存的模型 pose 与已有粒子/HUD/FBP 槽继续绘制，真实 Fence 仍正常建立。
- 组合测试还覆盖 1024/2048/4096 批次扩容、原始回退字节与像素一致，关闭后 GPU/direct 预算归零。
- 地形可变与持久映射两种路径均通过 256 KiB→512 KiB 扩容、排队绘制与复制像素一致、扩容申请失败保持旧内容、回收回调重入和未完成复制期间的回收测试。
- Forge/OptiFine G5 实际变换后的矩阵方法在 24 组移动相机对照中像素误差为 0，8/16 部件仍可合成一次提交。
- 构建日志为 .refactor-backups/1.0.18-build.log；最终原生日志、产物 SHA-256 和验证清单在 .refactor-backups/1.0.18-final/。原生验证使用本机 RTX 4060 Laptop 的隐藏 Pbuffer，没有启动游戏。
安装 build/libs/ice-rlcraft-optimizer-1.0.18.jar；继续录制时同时更新 ice-rlcraft-profiler-1.0.18.jar，删除对应旧版后重启。
Profiler 记录格式保持 ICECAP v5 和现有 F6 时间线。F6 仍切换能够即时关闭的优化。
没有自动修改游戏实例或启动游戏。离线验证用于确认失效链已被修复，实际 FPS 与慢帧收益需要游戏记录检验。
