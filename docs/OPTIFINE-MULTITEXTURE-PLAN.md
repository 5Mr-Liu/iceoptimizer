# OptiFine G5 多重纹理兼容方案

日期：2026-10-31。状态：设计方案，尚未实现；当前 auto-gl-paged 测试 JAR 不包含此兼容。

## 目标和已核实的原因

保持用户的各向异性过滤设置（当前为 8x）与 ICE 地形优化同时工作。保留启动时一次选择的 OpenGL 4.3 / 2.1 后端、2.1 固定共享页、构建和上传调度、空 VBO 修复、物品动画修复。

已检查实际 OptiFine 1.12.2 G5 类：

- Config.isMultiTexture 在 AF > 1 或运行中的 AA > 0 时返回 true。
- BufferBuilder 使用 quadSprites 保存每个四边形的贴图；相关顶点路径将 UV 转为 sprite 的局部坐标。透明排序会同步重排 quadSprites；BufferBuilder.State 也保存相关状态。
- G5 drawMultiTexture 绑定 sprite 的独立纹理。非透明层按第一次出现的材质组织绘制，草侧面覆盖纹理延后；透明层保持材质段的顺序，不能把所有同材质面提到一起。空 sprite 的处理也有既定规则。
- ICE 当前只上传顶点字节并使用单张图集绘制，没有保存 quadSprites；强行放行会丢失材质语义，可能产生错贴图。
- G5 OpenGlHelper.useVbo 的第一个禁用分支就是 isMultiTexture。本次崩溃发生在这一分支，经 ICE 专用判断抛出异常。
- G5 自身在 AF/AA 开启时拒绝加载光影包。本次兼容支持其正常多纹理地形模式，不把“8x + 光影包”视为已经支持的组合。

实际字节码分析保存在 build/crash-analysis-20261031/ 下。

## 1. 提取材质并随网格发布

新增 G5 BufferBuilder 的受限访问接口，在已有 CPU 准备阶段、builder 被重置或复用之前，提取有效四边形对应的 sprite。不得长期引用 builder 的可变数组，也不得在工作线程调用 GL。

将信息压缩为材质表和材质对应的四边形范围，携带到 Prepared、已发布 Mesh 以及最终绘制命令。使用已有局部 UV，复用 OptiFine 已创建的独立纹理和过滤参数；不重新创建纹理图集、纹理数组或完整 CPU 顶点副本。普通单图集网格不分配这些材质数组。

索引生成同时处理材质范围、CPU 面剔除、65,532 顶点分段和 2.1 页边界。每条命令包含正确的纹理、索引偏移、顶点基址和区块变换。只有完整上传成功后发布；任务取消、旧资源代次、上传失败都不能留下可绘制的半份数据。

## 2. 保持 G5 的绘制顺序

以 G5 自身的材质提交规则为基准，覆盖非透明层同材质范围、草侧面覆盖层和空 sprite。保留 ICE 对已证明不可见面的剔除。

透明层使用已排序的几何和同步排序的 sprite 信息，只合并相邻同材质范围。透明帧队列反转区块时，不能连带反转该区块内的四边形或材质段。跨页仅拆命令，不按页或纹理重新排序。

## 3. 两套后端共用材质命令

| 后端 | 提交方式 |
| --- | --- |
| OpenGL 4.3 | 对最终顺序中连续同纹理的命令使用现有 MDI，纹理变化时结束当前批次并绑定下一张纹理。原单图集路径仍使用原批处理。 |
| OpenGL 2.1 | 沿用共享固定页；按材质段执行普通索引绘制，只在纹理或页实际变化时重新绑定。 |

不引入纹理数组、bindless、扩展组合探测或新的后端选择路径。采样继续使用原来的二维纹理与光照纹理；保存和恢复纹理单元、绑定、程序和缓冲状态，并与 GlStateManager 的状态缓存保持一致。

代价主要是材质元数据和额外纹理绑定/绘制调用；纹理交替越频繁，批次越多。普通单图集路径不承担逐材质扫描、数组分配或额外绑定开销；不能提前承诺 8x 模式的 FPS 与单图集相同。

## 4. 收窄地放行并补齐生命周期

多纹理适配结构确认可用后，只修改 ICE 专用地形 VBO 判断中的多纹理禁用条件；保留全局 useVbo、真实硬件检查、区域渲染保护条件。用户无需手改 VBO/AF 设置，不自动改画质或回退后端。

多纹理兼容属于必要的材质解释，F6 对照路径也必须捕获并使用材质信息。仅修改 ICE 主绘制路径而保留原纯 VBO 对照路径会在 F6 暂停后产生错贴图，不能作为完成状态。

资源包重载、AF/AA 模式变化、世界切换时走现有任务取消/排空/重建流程；材质携带资源代次，禁止旧任务在新纹理代次发布。不能跨重载缓存已失效的 GL 纹理编号。设置变化只重建材质及网格，OpenGL 后端不重新选择。

检查失败的报错需说明具体条件（如多纹理适配结构不匹配、区域渲染条件不满足），避免继续使用现在笼统的 VBO 拒绝消息。

## 5. 验收

1. 真实 G5 构建、状态保存/恢复、透明重排、上传和 F6 完整调用链测试；包括 builder 复用、任务取消、资源代次变化及释放。
2. AF 关闭、2x、4x、8x、16x（以设备支持为准），另列 AA 开关组合；普通单图集模式做回归，不把 AF 通过等同 AA 通过。
3. 以 G5 原多纹理输出为参考，比较实际独立纹理绑定、斜视纹理过滤、透明水/玻璃、草侧面覆盖纹理、动态地形贴图和状态恢复。覆盖多材质交替、跨 65,532 顶点和跨页情况。
4. 当前整合包 8x 配置启动到世界，测试移动加载、卸载重建、F6、资源包重载和关闭地形动画后的双截棍；用户未要求启动游戏前，不自行运行完整游戏。
5. 分别记录 4.3 / 2.1 下的纹理绑定数、绘制调用数、CPU/GPU 工作帧分位数、峰值缓冲及进程内存。离屏检查不能替代 Android/gl4es 实机性能测试。

实现顺序：材质快照与顺序测试 → 两后端提交 → F6/重载与取消 → 放行专用 VBO 检查 → 整体回归与新测试包。完整数据链通过前不交付仅删除检查的 JAR。
