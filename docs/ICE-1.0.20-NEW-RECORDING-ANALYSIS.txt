ICE 1.0.20 — 2026-10-10 新实机记录分析
=======================================

结论
----
用户“关闭后更快”的观察有记录支持。ICE 确实执行了大量优化路径，同时
存在没有被上一轮局部改动解决的额外成本，整帧净收益仍不可靠。
测试时玩家在同一区域移动或转视角，所以差额不能全部当成 ICE 的严格
因果效应；较接近负载的相邻短窗仍显示关闭后平均帧时间下降。
本轮只分析记录和源码，没有修改生产代码、配置、游戏实例或安装文件。

明确发现的额外成本
------------------
1. HUD 的状态保存和恢复工作重复。
   LwjglHudRenderer.flush 每个小批次 glPushClientAttrib / glPopClientAttrib，
   同时重新设置顶点布局。切换至少 5 秒后的 30562 个 ON 客户端栈样本里，
   1983 个包含此 flush；其中 1223 个叶子落在 glPushClientAttrib。
   HudRenderBridge.post 在每个 Forge HUD 事件后清空状态镜像，再调用
   ModernRendererRuntime.resynchronizeHudState 查询一整套 GL 状态；
   后面是否还存在现代 HUD 几何，并不影响它已经付出的查询成本。
   新采样有 524 个 HUD 状态同步样本，其中 491 个落在 GetInteger。

   另有 82 个 Throwable.fillInStackTrace 样本来自
   LwjglLegacyStateRestorer.restoreLegacyCallSiteState：事件后矩阵镜像已
   失效，下一次通用旧路径恢复因“legacy call-site state is unknown”抛出
   异常，LegacyGlIsland.prepareOuterEntry 捕获后继续。现代 HUD flush
   自己已经还原 native 状态，却再次走通用全状态恢复，制造无效工作。
   上述是采样次数，不是实际调用次数，不能直接换成毫秒或精确 CPU 百分比。

   修复方向：每个 HUD buffer slot 用固定布局 VAO；事件前只完成真实队列
   flush 和必要恢复；事件后只标记镜像失效，到下一次实际接收 HUD 几何时
   再同步一次。移除 HUD 这条重复通用恢复，而非吞掉更多异常或关闭优化。

2. 软件地形遮挡在低收益场景仍付出较大准备成本。
   CurrentFrameTerrainOcclusion.capture 在主线程上传路径上扫描、分类并
   归并遮挡面；filter 每帧查询 WeakHashMap、投影边界、维护堆及栅格化。
   切换至少 10 秒后 29364 个 ON 样本中，filter 1114、capture 969；这些
   样本证明实际额外工作，不代表精确的整帧耗时占比。
   某对相邻 renderer 快照净增：549720 次遮挡测试、2211840 个处理面，
   隐藏数增加 0。此计数说明那一段没有省掉网格绘制，仍付出了遮挡计算。
   原始快照为 20261010-091432-935 和 20261010-091520-327，published_frame
   为 60617 → 61697，净增 1080 帧。平均每帧约处理 2048 个面。
   OFF 时 renderer 快照可能保持最后 ON 状态，不能把目录名或导出时间
   直接视作这段计算的起止时间；这里比较的是同代 renderer 的累计差值。

   修复方向：把不随相机变化的边界、朝向和矩形构建并入区块编译结果，
   复用已有分类数据，主线程上传只发布结果；用紧凑层级数据减少当前视角
   的投影和光栅工作。它需要改算法和数据流，不是加一个在线 FPS 门槛。

3. 地形存储接近预算上限，现代与原路径混合提交仍然碎片化。
   多个快照中 256 MiB 共享 GPU 预算只剩约 0.37–0.47 MiB；地形占主要
   空间，上传拒绝计数持续增长。现代提交平均约 2 个 command 就一次 draw，
   旧 VBO 穿插又结束当前 shader 范围、重复矩阵与顶点布局设置。
   ON >=10 秒的样本中，地形 render 3901，原 VBO drawLegacyVertexBuffer
   1916，shader drawScoped 985，endNativeRun 159。不能仅因拒绝计数很大
   就认定分配器为最大主因；分配/回收路径在采样中的份额较小。
   shader、indirect 故障计数为零，没有证据表明本次是安全门禁自动停用。

   修复方向：普通未入 arena 的 VBO 也缓存布局/原点信息，使用同一 shader
   和位移数据，保持原顺序跨这些网格继续提交，减少两条路径的切换成本。
   更长远需要改善存储与批次的组织。不能重排画面或假装不同 VBO 可直接
   拼成一次 MDI，也不能只增大预算掩盖碎片。

上一轮局部改动为什么没解决
--------------------------
模型参数去重和组合模型取消 GPU 读回针对的只是局部成本。新记录中，
pose flush 样本不多、冷组合读回没有被采到，HUD 和地形上述开销仍持续。
RC 工作区主要减少生成时分配，不能解决每帧客户端状态切换。
普通单部件模型仍有 VAO bind / DrawArrays 成本，不能把“走了 MODERN”
直接当成“比原 display list 更快”。
因此后续优先处理 HUD 状态管理、软件遮挡准备和地形混合提交，而不是
继续只减少冷路径的小调用，或添加收益检测、静止条件和自动停用门禁。
