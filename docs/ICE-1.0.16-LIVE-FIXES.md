# ICE 1.0.16 实测问题修复

本次根据 2026-10-10 的 18 份录制修复。录制显示实体后端因 CPU 矩阵认证失败被隔离、地形 Arena 受 128 MiB 封顶和碎片影响而大量退回旧上传、模型即时 VBO 状态切换开销明显，以及 OTG / Recurrent Complex 生成热点。

## 渲染

- 普通即时模型 VBO 和普通顶点数组批次使用 GPU 当前矩阵，不再要求 CPU 矩阵镜像完整。只有真正使用 CPU model-view 数据的姿态合批需要它；姿态合批失效时结束延迟矩阵作用域后继续普通绘制，不牵连整个实体/TESR 后端。
- 模型共享 VBO 页和姿态合批网格分别复用自己的 VAO 顶点布局，减少逐部件重复设置指针与保存、恢复数组状态。即时部件提交由 10 次 GL 调用降为 3 次；同页普通数组批次的 N 个部件为 N+2 次调用。上下文、资源代次、已提交绘制不得重复回放等条件仍保持。
- 地形改为按需分页分配，容量受现有 GPU 总预算约束，取消额外的 128 MiB 单缓冲封顶。分配处理页边界、碎片、已完成的退休区间和替换上传空间；跨页提交保留原绘制顺序。
- 空地形页解除 VAO 引用后退役；模型 VAO 随所属网格退役，避免驱动继续保留已删除 VBO 的存储。连续同区域的 OptiFine 旧网格合并结束提交。
- 软件遮挡在网格上传时复用解码结果和图集透明性查询；视角与人物移动不构成启用条件。

## 世界生成

- BO4 读取资源时按列稳定分组，避免每个列坐标重复扫描完整方块表，保持列内原顺序。
- OTG 数组池清理按本次借用的有效前缀进行，避免小请求反复清理历史最大数组尾部；数组对象、池复用及清零语义保持。
- Recurrent Complex 的同一次结构云构建复用重复坐标的插值结果，缓存生命周期限于该构建，坐标完整比较；不改变随机数调用与结构生成顺序。

没有引入在线收益测试、AB 对照准入、预热计数、摄像机静止条件或新硬件白名单。F6 仍控制可即时切换的优化；记录功能不参与优化决策。

## 录制与比较

同时更新 Optimizer 和 Profiler 到 1.0.16。两个模组仍各自可以单独安装。

- F6 状态变化直接进入 `hitches.json` 的 markers，自动捕获的前窗口也保留这些事件；切换本身不额外触发卡顿捕获。
- `timeline.csv` 新增 `optimizer_runtime_state`：`1` 开启，`0` 暂停，`2` 该采样区间发生切换，`-1` 未接收到优化器状态。该状态只描述运行时总开关，不表示每个子模块的实际工作覆盖率。
- `fps` 按实际采样间隔计算，保留 `frame_count` 与 `sample_interval_ns` 供精确汇总。比较平均出帧率使用 `sum(frame_count) / sum(sample_interval_ns) * 1e9`。
- 二进制文件版本为 ICECAP v5：在每个 TimelinePoint 原 v4 内容之后追加 `int frame_count`、`long sample_interval_ns`、`byte optimizer_runtime_state`。其他段落顺序保持；旧录制不会重写。
- 导出时的 `optimizer-renderer.txt` 仍是累计快照，不能把它当成单次录制内的调用量。
- 地形诊断新增最大虚拟容量与当前物理页字节数。分配拒绝数统计的是尝试次数；一次重试后仍可能成功复用旧槽，不能将其直接等同于退回旧上传次数。全局 GPU 总预算耗尽时仍可能使用旧上传路径。

F6 切换仍需重建地形；比较同位置、同视角下重建结束后的录制，排除状态为 `2` 的区间和仍在重建的过渡阶段。移动场景应使用相同路线。此处是测试方法，不是运行时门禁。

## 构建

Java 8。默认构建使用 IvToolkit 的编译期依赖；可用 `-PivToolkitJar=<IvToolkit-1.3.3-1.12.jar>` 指向现有模组包进行离线构建。该依赖不打入 ICE，游戏仍使用模组包自己的 IvToolkit。

```powershell
.\gradlew.bat build optimizerBundleZip --no-daemon
```
