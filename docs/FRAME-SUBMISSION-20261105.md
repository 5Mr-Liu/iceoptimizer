# 帧提交与索引准备优化候选

日期：2026-11-05。模组版本仍为 1.20.2，构建标识为 `frame-submission-20261105`。
基于本轮开始时的工作区，包括已有 OpenGL 2.1、多重纹理与生命周期修改；不是从已发布 v1.20.2 重建的独立补丁。

## 查实的开销与修改

`NativeTerrainRenderer.prepare` 在绘制前生成变化网格的索引，再打包四层命令。这段工作不属于区块上传的约 2ms 时间片。旧实现逐四边形写索引，GL43 后端每次 prepare 都上传完整的 36 字节/绘制记录，即使内容没有变化。

- `NativeTerrainFaceIndex` 在已有工作线程分类时额外记录每 64 个四边形的面类型并集。生成索引时，全部保留的范围直接复制连续索引，全部排除的块直接跳过，混合块沿用逐面判断。若各完整块都必然混合，直接走独立的原顺序循环，避免块遍历开销。没有改变可见性判定、透明顺序或四边形末顶点。
- `NativeTerrainSequentialIndices` 共享大小端各 128 KiB 的连续索引字节表，只为每个使用线程保留两个游标。透明层、光影布局和多重纹理子范围也使用同样的整段复制，局部索引基址保持原值。
- `NativeTerrainCommandData` 比较已成功上传的完整整数记录。内容完全相同则不上传；只有位置/缩放前缀变化时上传 16 字节/绘制记录；绘制数量、索引、基址或顺序变化时完整上传。GL43 保留稳定常驻命令存储与暂存复制，不恢复曾导致 Intel 错误的间接缓冲 orphan。复用 IntBuffer 视图，避免每次上传创建视图对象。

索引元数据增加约每 64 个四边形一个字节及每网格一个整数；命令缓存额外保留最大包大小的整数数组。CPU 仍逐帧准备绘制记录，本次没有消除几何存储扩容、GPU/驱动等待或服务端工作。

## 对照测量

脚本：`tools/run-native-frame-submission-probes.ps1`。按 baseline、candidate、candidate、baseline 串行运行，最终记录位于 `build/frame-submission-20261105/final-probes/`。比较基线是修改前冻结的两个源文件：

- NativeTerrainFaceIndex.java SHA256：`966AECAEBA3C2E91E8009A61A3C7B837541D17E3C9258575408BDEA4618AADFE`
- NativeTerrainGl43.java SHA256：`72AA9303217AAAD8D3AA62D56126963C3BDF0E82B9EDA15C02FE86DBA8CFE5E9`

CPU 合成工作负载每个样本处理 64 个网格、4,194,048 个顶点，预热 150 次、测量 400 次。下表为两次运行的 P99 范围，单位 ms，不是游戏帧时间：

| 索引场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 连片面，全部保留 | 1.921–2.026 | 0.240–0.258 |
| 连片面，保留一半 | 1.544–1.686 | 0.234–0.281 |
| 交错面，保留一半 | 1.740–1.855 | 1.427–1.557 |
| 无过滤连续索引，连片夹具 | 1.100–1.166 | 0.229–0.299 |

交错面保留一半的中位数基本持平：基线 0.782–0.814ms，候选 0.786–0.838ms，不宣称所有输入均加速。各轮生成字节总量和校验值一致；逐字节正确性由回归另行验证。

GPU 探针使用实际 NVIDIA RTX 4060 Laptop / OpenGL 4.6 上下文，每包 4096 条记录，预热 200 次、测量 800 次。探针专用 glFinish 包含上传完成等待，但不绘制完整游戏场景，也不用于声称 FPS 提升。

| 命令上传场景 | 修改前 P99/ms | 修改后 P99/ms |
| --- | ---: | ---: |
| 内容相同 | 0.562–0.869 | 0.112–0.165 |
| 仅相机位置变化 | 0.606–0.846 | 0.205–0.246 |
| 命令变化、完整更新 | 0.586–0.636 | 0.214–0.302 |

完整更新也受到视图复用、JIT 和驱动测量波动影响，不把差值全部归因于传输字节减少。候选仍有约 2.3ms 的孤立上传探针最大值；上述结果不能证明消除了用户遇到的严重跳帧。
