执行目标
寻找、实现并验证更有效的整体优化方法，提高 Dregora 1.12.2 普通游玩时的
原生帧率与帧时间稳定性。技术路线可以重构或替换现有渲染适配方式，不再把
工作限制为排查、修补 ICE 现有负优化。优先按真实耗时和收益空间选择工作。

此前相对关闭 ICE 提升 50% 的要求仍作为目标，不假定某种算法一定能做到。
保留关闭 ICE 的同条件基线、当前版本对照和实际收益验证。局部探针的倍率、
调用数减少或编译通过，均不能替代普通游玩的实测收益。
保持画质、视距和玩法；继续停止战斗专项研究与战斗测试夹具工作。

研究决策
主线：从区块构建开始统一管理渲染数据，研究完整的区域渲染路径。
让稳定的区块元数据、网格和绘制批次长期保留，变化发生时更新依赖数据；
在渲染帧内主要执行相机相关判定与提交，减少从原版对象和 GL 调用反向
恢复场景信息的工作。现有 ICE 组件可以复用，但不要求保留当前接管结构。
这是新的实现方向，尚未完成或证明整包收益。

完整替换实现已有首轮证据：同包无 ICE 的普通移动测试约 198.29 FPS，
加入 Nothirium 0.4.9-beta 后约 342.85 FPS（单组 +72.90%）。这不是
ICE 自身成果，也尚未通过相同画面、兼容性和重复性验收。优先验证这条
完整路径，按结果选择独立地形后端整合或自有架构实现，而非退回微调旧层。
过程、指标和限制见 ICE-RENDERER-REPLACEMENT-RESEARCH-20261012.txt。
同口径粗粒度诊断进一步显示，地形绘制约 1.898 -> 0.054 ms/帧，是
主要差值。保留固定管线的 GL15 对照约 286.29 FPS（基线 200.18），
远处景物目视更接近原版。两种后端诊断均非正式验收；主线现具体为完整
地形管理与提交路径，并解决默认后端的雾/视觉差异、扩展自然地形对照。

已核对的参考与可用思路
1. Celeritas 的源码声明 Forge 1.12.2 支持 Java 8 + LWJGL 2。
   本次读取 GTNewHorizons/nh-main 镜像源码，具体实现包括：
   - RenderRegion 以 8×4×8 个 section 组织区域与存储。
   - SectionLattice 用相机附近的平坦数组、打包元数据和边界哨兵进行遍历。
   - CachedBatch 在 section 顺序、相机有效范围及存储状态适用时复用批次。
   - 构建结果按区域发布；可见性搜索与数据修改有明确同步边界。
   - 1.12.2 的 ClonedChunkSectionCache 支持快照复用和显式失效。
   这些是可研究的结构，不是一次多绘制调用或扩大缓存就能获得的收益。
   异步搜索包含 join，不能宣称“放到线程上就消除了主线程等待”。
   README 提示官方分发为源码、维护与测试有限；不能直接认定兼容 Dregora。

2. Nothirium 可作为另一种区块渲染实现的对照候选。
   作者页面列出 OptiFine Smart Animations、自定义方块渲染层、VanillaFix
   textureFixes 等兼容边界。当前整合包含 OptiFine G5、ChunkAnimator、
   RenderLib、FermiumASM 及多个 Mixin 模组，必须实测而非按名称推断兼容。
   不把删除视觉特性之后的帧率提升算作同画质收益。

3. HUD 保留在范围内，但按成本安排优先级。
   优先保存已知元素的布局/几何和完整依赖；数据、资源、窗口或动画改变时
   更新。Forge 事件、副作用、动态内容与原有绘制顺序必须继续执行。
   不把整体 HUD 降频当作优化，也不因为前文强调 HUD 就忽略更大的地形成本。

研究与验证方法调整
- 将完整外部实现作为比较对象，区分“完整数据路径更有效”和“某个 API 更快”。
- 针对已加载区域的站立转向、普通移动、方块变化与常规 HUD 使用进行验证。
  主线不再局限于跑图生成，也不添加战斗专项。
- 对新路径记录 CPU 主线程、GPU、上传/同步和慢帧，确认节省落在哪个区间。
- 算法正确性检查服务于具体改动；不为每个微秒级猜想建立新的复杂框架。
- 决定保留与否看整包净收益、兼容性和维护成本；允许替换整套旧设计。

现有证据如何使用
此前 ICE 候选的单组普通游玩对照为关闭 ICE 195.793544 FPS、Build27
181.281975 FPS（-7.41%），自然实体数量不同，不能隔离每个改动的因果收益。
Build27 是未通过整包验收的候选，未部署到原游戏。

最新粗粒度诊断中，地形层约 2.16–2.31 ms/帧、HUD 约 0.23–0.25 ms/帧、
OTG 雾效两个事件合计约 0.16–0.17 ms/帧。这轮窗口并非全程活跃，且带插桩，
只能用于定位工作量，不作为正式 FPS 对照或精确收益预测。包含关系不得相加。
相对约 195.8 FPS 提升 50%，需要平均帧耗时从约 5.11 ms 降到约 3.40 ms；
仅围绕 HUD、映射查找或雾效的小改动不足以支撑这个目标。

OTG 雾效缓存原型已做数值检查，暂不投入生产整合。它只是候选工具，
不再驱动当前主线；后续只有整体性能证据支持时才重新考虑。
