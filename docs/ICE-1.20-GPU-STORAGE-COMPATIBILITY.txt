ICE 1.20 修订 10：GPU 缓冲区分配判定与核显验证
日期：2026-10-16

报告与范围
-----------
用户报告刚进入游戏就退出，堆栈为 Rendering chunk -> NativeTerrainStorage.ensure:30：
ICE terrain GPU allocation failed: 1282 at 5505024。
设备为 Intel Iris Xe / OpenGL 4.6 / 30.0.101.1692，Java 8，ICE 1.20。
报告不含制品哈希，不能仅凭版本号区分修订。此路径在修订 9 仍保留旧判定。
1282 是 GL_INVALID_OPERATION，而不是 GL_OUT_OF_MEMORY；5505024 是申请字节数。
用户已明确这次发生在进入游戏时，不能继续假设需要按 F6 才触发。

代码证据与修复
---------------
旧实现 glBufferData 后读取 glGetError，只要非零就删除新缓冲区并抛异常。
glGetError 读取的是整个上下文的未处理错误，不证明错误来自紧邻的分配调用。
因此之前的渲染操作留下 1282 时，即使分配成功，ICE 仍会误报并退出。
报告本身不能确定最早产生 1282 的 OpenGL 调用，也不能证明所有 Intel 驱动问题同源。

新实现通过 OpenGL 3.2 的 glGetBufferParameteri64(GL_BUFFER_SIZE) 检查新对象
实际字节数，不消费或清除其他调用留下的错误。只在创建/扩容时查询，不增加每帧
或每次上传的大小检查。ICE 自有地形要求 OpenGL 4.3，因此此 API 不提高要求。
真正没有分配到所需大小时仍会失败，并记录 requested、allocated、stride。
失败清理未提交的新对象，保留旧对象和容量；成功后将保存的旧对象绑定替换为
新对象，避免重新绑定已经删除的编号。通用路径不按 Intel/NVIDIA 品牌分支。
保留优化默认开启、F6 开关和此前光影切换修复，没有新增 HUD、性能门禁或回退。

进一步定位：间接绘制缓冲区
---------------------------
第一轮仅修分配判定的候选包（SHA256 1017B391B1E9C08375E47B462485D311C0BB89C2CFE56DB1183E01672A506B58）
在 Intel UHD 上完成 75 步且正常退出，但无光影截图只有实体、没有地形。
因此未把“不再崩溃”当作完成，也没有把此候选交付为最终修复版。
独立真实驱动回调进一步定位到 glMultiDrawElementsIndirect：原来每帧对
同一个同时承载实例属性和间接命令的对象调用 glBufferData，替换数据存储，
Intel 上第二轮绘制出现 GL_INVALID_OPERATION 1282。此时几何绘制失败，
遗留错误随后可能被旧 ensure 错误归因到分配。报告电脑是否完全同源仍需复核。

诊断结果：移动位置属性从 8 到 0、改成单条 indirect、改为 arrays indirect、
改在 GL_DRAW_INDIRECT_BUFFER 目标上传都不能消除 1282，未用于生产实现。
保留存储的 glBufferSubData 与直接绘制能避免该错误，但未将这些诊断分支
直接加入正式模组；没有把四边形改为三角形，也没有按品牌改成逐区块绘制。

最终命令缓冲区复用 NativeTerrainStorage：保持常驻对象和存储，每帧仅通过
现有 copy-only 暂存缓冲区上传，再 glCopyBufferSubData 更新命令内容。
只有暂存对象调用 glBufferData；容量增长时建立新常驻对象，刷新 VAO 的
实例属性指针。独立维护 vaoCommands，避免只有几何缓冲变化时才刷新。
无命令帧不提交空复制；光影路径只读 CPU 记录，不再上传未使用的间接命令。
核显与独显使用同一实现，仍为原四边形、16 位索引和 MultiDrawIndirect，
没有硬编码设备 ID、显存大小、CPU 数量或某台电脑的参数。

外部真实驱动验证
-----------------
工具：tools/NativeTerrainStorageProbe.java、tools/run-native-storage-probe.ps1。
测试夹具不进入正式 JAR，不使用 Minecraft 世界，也不是 FPS 测试。
先故意在绑定 0 的缓冲目标上调用 glBufferData，产生待处理的 1282，然后调用
原封不动的修订 9 JAR 中的 NativeTerrainStorage.ensure(180000)。
独显与核显都复现完全一致的异常文本：1282 at 5505024。
这证明错误归因缺陷能造成该异常，不声称完全重现用户的所有模组状态。

替换、旧对象删除和无需扩容时不更换对象。原错误保留给其原调用方检查。

没有改变用户原游戏或原 Java 的显卡偏好、驱动、全局显示模式。
